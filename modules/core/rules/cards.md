# Cards

A card is one question that needs the user's decision. An agent raises a card instead of guessing. The user answers it from a frontdesk, a phone, or an issue comment.

- **Background first, then the question, then the proposals.** The user decides without opening anything else. Mark every proposal 提案 (proposal), so no proposal reads as a settled call.
- **A code-detail card carries one recommended proposal. A design, product or pitch card carries none up front.** It offers a "what would you pick?" choice that reveals the agent pick and its reason only when chosen, because a pick shown first anchors the user. The agent writes its pick on every card, hidden on design cards.
- **One decision per card.** A second decision on the same card gets answered by accident or not at all. Split it into two cards.
- **Record what the agent already checked.** One line on the card. The user does not repeat a search the agent has already run.
- **An unanswered card resurfaces after a set time.** It never vanishes. The mechanism arrives in a later phase of the frontdesk plan; until then, a card waits where it was parked.
- **Never refer to an option by a label.** No "option B", no "the second one". Write the whole option out every time, because the reader should not look anything up.
- **Names, labels and statuses are in English.** The 提案 mark is the one exception.

Why the order matters: a question that comes before its background makes the reader hold an open question while reading the facts, then reread the facts.
